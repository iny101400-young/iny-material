# iny-material

**흩어진 자료를 전부 Markdown 으로 바꿔 재료 창고를 만드는 Claude Code 스킬입니다.**

이력서, 포트폴리오, 발표자료, 메모, 링크.
pdf·docx·hwp·이미지로 흩어져 있으면 AI 가 읽지 못합니다.
읽을 수 있는 하나의 형식으로 바꿔 한곳에 모읍니다.

에셋엔진 워크플로우의 **01단계**입니다. `v1.3`

---

## 이 스킬이 하는 일과 안 하는 일

| 합니다 | 안 합니다 |
|---|---|
| 형식 변환 | **쓸모** 고르기 |
| 출처·소유권·날짜 기록 | 분류·태그 |
| 목록 만들기 | 요약 |

**무엇이 쓸모 있는지는 여기서 정하지 않습니다.**
기준이 있어야 고를 수 있는데, 그 기준은 다음 단계에서 나옵니다.
여기서 미리 고르면 나중에 전부 다시 골라야 합니다.

### 대신 세 가지는 여기서 거릅니다

쓸모의 문제가 아니라서 미룰 수 없는 것들입니다.

| | |
|---|---|
| **자료가 아닌 것** | 설치된 코드, 캐시, 빌드 산출물. 프로그램이 만든 것입니다 |
| **남의 저작물** | 섞여 있으면 나중에 **내 글처럼 발행될 수 있습니다**. 다만 버리진 않습니다 |
| **개인정보** | 주민등록번호·주소 같은 것. 늦게 거를수록 새어 나갈 곳이 늘어납니다 |

**폴더 이름만 보고 자르지 않습니다.** `uploads` `public` `.claude` 처럼
애매한 이름은 안을 세어 보여드리고 **물어봅니다.**
`.claude` 안에 사람이 쓴 설계 문서가 들어 있던 적이 있습니다.

### 남의 자료를 통째로 버리지 않습니다

내 것이 아니라고 다 빼면 **배우던 시절의 자료가 통째로 사라집니다.**
강의 교재, 스터디 자료, 남의 발표자료. 시작하는 분일수록 이 비중이 큽니다.

| | |
|---|---|
| **내 것** | 그대로 씁니다 |
| **출처를 밝히고 쓸 것** | 남의 것이지만 **누가 만든 것인지 밝히면** 인용할 수 있습니다 |
| **안 쓸 것** | 밝혀도 못 쓰는 것 |

가운데 갈래를 **어디에 넣을지는 직접 고르십니다.** 스킬이 정하지 않습니다.

### 개인정보는 AI 에게 넘기기 전에 가립니다

**순서가 규칙보다 중요합니다.** 요약이나 갈래 나누기를 AI 에게 시키는 순간
본문이 통째로 넘어갑니다. 그 뒤에 가려봐야 값은 이미 밖에 있습니다.

그리고 **신분증·급여·계약·진단서 같은 개인 서류는 열지도 않습니다.**
개수와 갈래만 세어 보여드리고, 그중 쓰실 게 있다면 그때 엽니다.
**막은 목록은 제안이지 판결이 아닙니다.**

## 설치

```bash
git clone https://github.com/iny101400-young/iny-material.git
cd iny-material
bash install.sh ~/내작업폴더
```

경로를 안 주면 `~/asset-engine` 에 만듭니다.

설치되는 것은 두 가지입니다.

| | |
|---|---|
| 스킬 | `~/.claude/skills/iny-material/` (`SKILL.md` 와 `scripts/`) |
| 작업 폴더 | 지정한 경로에 `raw/` `wiki/` `outputs/` 생성 |

## 쓰는 법

작업 폴더에서 Claude Code 를 열고 이렇게 칩니다.

```
재료화 시작
```

그러면 안내문이 나오고, **자료가 어디 있는지** 물어봅니다.
경로를 주면 형식별로 몇 개인지 세어 보여주고, 확인 질문 네댓 개를 거쳐 전부 변환합니다.

## 나오는 것

```
raw/
  web/  pdfs/  images/  notes/  docs/
.kb/manifest.json
제외목록.md
```

파일마다 머리에 이게 붙습니다.

```yaml
---
source: 원본 URL 또는 파일 경로
ingested_at: 2026-08-25T13:00:00Z
type: web | pdf | image | note | doc
status: uncompiled
owner: self | others | unknown
---
```

| | |
|---|---|
| `status: uncompiled` | **아직 안 쓴 재료**라는 표시입니다. 다음 단계가 이걸 보고 새로 들어온 것만 처리합니다. 자료가 늘어나도 처음부터 다시 돌리지 않습니다 |
| `owner` | 내 것인지입니다. 판단이 안 서면 `unknown` 으로 두고 다음 단계가 다시 묻습니다 |

해당할 때만 붙는 줄이 더 있습니다.
`sensitive` (개인정보 **종류만**) · `layout_lost` (표 모양이 사라졌음) ·
`described: no` (이미지를 아직 글로 안 옮겼음) · `extracted_by`.

### 제외목록.md

**뭘 왜 뺐는지 남습니다.** 다시 돌려도 여기 적힌 것은 또 들어오지 않습니다.
직접 열어 고칠 수 있습니다. `넣기` 로 적으면 폴더째 뺀 안에서 몇 개만 살릴 수 있습니다.

## 알아둘 것

**원본은 건드리지 않습니다.** 읽고 복사만 합니다. 지우거나 옮기지 않습니다.

**한글 파일(.hwp)은 도구 없이도 글자를 뽑습니다.** 딸려 오는 `scripts/extract.py` 가
파이썬 표준 라이브러리만으로 처리합니다. `hwpx` `pptx` `xlsx` 도 같이 됩니다.
다만 **표의 행·열 관계는 사라집니다.** 그럴 때는 머리말에 `layout_lost` 를 남기고 알려드립니다.
`hwp5txt` 가 깔려 있으면 그쪽을 먼저 씁니다. 품질이 더 낫습니다.
HWP 3.x 이하와 암호가 걸린 문서는 못 엽니다. 조용히 넘기지 않고 이름까지 알려드립니다.

**이미지는 기본이 목록 등재입니다.** 안에 뭐가 그려져 있는지 글로 옮기려면
한 장씩 열어야 해서 오래 걸립니다. 몇 장을 옮길지 물어봅니다.
어떤 이미지가 필요한지는 다음 단계에서 컨셉이 잡힌 뒤에 알 수 있습니다.

**옵시디언 볼트가 자료 안에 있으면** 통째로 넣을지, 빼고 갈지, 건너뛸지 물어봅니다.

**이미 다른 사이트에 올려둔 자료가 있으면** 알려드립니다.
같은 글이 두 곳에 있으면 나중에 어느 쪽이 효과 있었는지 비교할 수 없게 되기 때문입니다.

## 필요한 것

| | |
|---|---|
| [Claude Code](https://claude.com/claude-code) | 스킬은 여기서 돌아갑니다 |
| macOS | `textutil` 로 doc·docx·rtf 를 읽습니다 |
| `python3` | 한글·pptx·xlsx 폴백용. 맥에는 이미 있습니다 |
| `pdftotext` | PDF 용. 없으면 Claude 가 직접 읽습니다 |
| `pyhwp` | 한글 파일 품질을 더 올리고 싶을 때만 (선택) |
